## The failure that had to be fixed first

`ghost-ai-writer-web` never came up: `npm ci` died on the clean clone with
`Missing: lru-cache@11.5.3 from lock file` — `package-lock.json` was out of sync with
`package.json` (11 missing lines). Reproduced by cloning fresh on Node 22 and running
`npm ci`; fixed by regenerating the lock with npm 10.9.2 (the version Render ships),
then verifying `npm ci` + the exact build command under a 460 MB heap cap (the free
instance has 512 MB). Build: 15 s, no OOM.

Two things were *not* the cause, despite looking like candidates: the Dockerfile steps
(verified in a clean directory: 13.6 MB release binary) and blueprint schema validation
(`render.yaml` validates against `https://render.com/schema/render.yaml.json` with both
the old and new `plan` value — the schema does not constrain plan names, so the plan
plural change was cosmetic, `starter` → `0.5c-512mb` per the docs' plan table).

Two services, one repo, defined in `render.yaml` at the repo root. Nothing here is
hypothetical: the Rust release binary, the token gate, and the Nitro node-server
bundle were all built and run locally before writing this.

## What gets deployed

| service | runtime | what it is | cost |
|---|---|---|---|
| `gaw-api` | Docker (`backend/Dockerfile`) | axum + sqlx backend, SQLite on a 1 GB disk | starter ~$7/mo + $0.25/GB disk |
| `ghost-ai-writer-web` | Node 22 | the TanStack Start app as a Nitro `node-server` bundle | free tier |

Both fit inside the $50 credit for months.

## Steps (owner, ~3 minutes)

1. **Push the repo** — Render deploys from GitHub:
   ```
   gh auth login          # device code, then approve
   git push origin main
   ```
2. **Apply the blueprint**: Render dashboard → **New → Blueprint** → pick
   `mdmahinpro/ghost-ai-writer` → **Apply**. Or click
   `https://render.com/deploy?repo=https://github.com/mdmahinpro/ghost-ai-writer`.
3. **Copy the generated token**: `gaw-api` → *Environment* → `GAW_ADMIN_TOKEN`.
   It is generated by Render and never printed anywhere else.

## Verify it is actually live

```bash
curl -s https://gaw-api.onrender.com/health
# {"status":"ok","version":"..."}

# every /api route is gated: this must be 401
curl -s -o /dev/null -w "%{http_code}\n" https://gaw-api.onrender.com/api/v1/workspaces

# and with the token, 200
curl -s -H "x-api-token: $GAW_ADMIN_TOKEN" https://gaw-api.onrender.com/api/v1/workspaces
```

Queue real work and watch the worker finish it:

```bash
curl -s -X POST https://gaw-api.onrender.com/api/v1/keywords \
  -H "x-api-token: $GAW_ADMIN_TOKEN" -H 'content-type: application/json' \
  -d '{"workspace_id":1,"site_id":1,"keywords":["how to pause a phd when funding runs out"]}'

curl -s -H "x-api-token: $GAW_ADMIN_TOKEN" https://gaw-api.onrender.com/api/v1/jobs
curl -s -H "x-api-token: $GAW_ADMIN_TOKEN" https://gaw-api.onrender.com/api/v1/worker
```

Jobs land in `PARTIAL` after the four implemented stages — by design, stages 5–6
(`enrichment`, `validation`) are not written yet.

## Environment variables (gaw-api)

| key | value | why |
|---|---|---|
| `DATABASE_URL` | `sqlite:/data/gaw.db?mode=rwc` | must live on the mounted disk, or it is wiped on every deploy |
| `ROLE` | `all` | API + worker in one process; split into two services when load demands it |
| `GAW_ADMIN_TOKEN` | generated | gates every route but `/health`; unset = wide open, and the server logs a warning |
| `SEED` | `1` or empty | `1` creates 10 demo workspaces/sites |
| `PORT`, `HOST` | set by Render | the binary binds `0.0.0.0:$PORT` |

Real provider keys are **not** env vars: they are rows added at runtime through
`POST /api/v1/providers` (`base_url`, `model_id`, prices, key). Adding a provider
needs no redeploy.

## Known limits of this deploy

- SQLite on a single disk is fine for one instance; it is not multi-instance safe.
  Moving to Postgres is a `DATABASE_URL` change plus verifying the `FOR UPDATE SKIP
  LOCKED` claim path (unwritten, untested here — no Postgres available locally).
- Provider keys are stored as given, **not encrypted at rest**. Put a KMS/env secret
  in front of `key_enc` before real customers touch it.
- The web service is the existing client-side app (PGlite in the browser). It does
  not call `gaw-api` yet; wiring the SPA to the API is the next slice.
- Free tier spins down after idle, so the first request after a pause is slow.
  `gaw-api` is on `starter` precisely so the disk and the worker stay up.
